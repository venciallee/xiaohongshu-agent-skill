# xhs-topic

选题是每个内容号最贵的一步：选错了，后面封面、标题、卡片做得再好也救不回来。

## 读 / 写

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | `voice.md` | 写给谁、领域、选题类型、不写什么、特殊规则 |
| 读 | `sources.md` | 去哪找 |
| 读 | `audience.md` | 读者在搜什么、问什么（「有人搜」那一项靠它） |
| 读 | `playbook.md` | 验证过的规则，优先于这里的一切默认 |
| 读 | `topic.json` | 打分表和及格线（没有就用内置的） |
| 读 | `xhs pool list`、`xhs log list -n 20` | 池子里已有的候选、最近写过什么 |
| 写 | `xhs pool add` | 过了三问的候选进池子 |

所有文件都在 `$XHS_HOME`（默认 `~/.xiaohongshu`）。缺 voice.md 或 sources.md，先让用户 `xhs init` 并填好，别凭空选题。

## 1. 先看池子

`xhs pool list`。池子里有过线的、没过期的候选，先考虑它们：昨天没用上的好题，往往比今天新找的强。

## 2. 扫信息源（只读）

按 `sources.md` 的顺序看。只挑**读者能用的东西**：做法、清单、对比、踩坑、新东西怎么用。新闻、事故、榜单只记下来当钩子，不当主体。

**只读不改。** 在任何平台上都不点赞、不转发、不关注、不评论、不发帖。用用户已经登录的浏览器、用户在场，人的速度；或者用户截图 / 粘贴。不写爬虫，不用第三方抓取服务。

同时在小红书搜索框里搜一下这个题：同题笔记现在有多少、写成什么样。你的版本必须有它们没有的那一半。

## 3. 每个候选先写洞察句，过三问

洞察句是一句**原材料里没直接写、但你看完能说出来**的话。三问，过不了直接丢：

1. **原文里搜不到。** 原文一字一句写着的，那是摘要，不是洞察。
2. **删掉这句，整篇就成了搬运。** 删了没影响，说明它不是骨架。
3. **有人会反驳。** 没人会反驳的话，也没人会停下来看。

## 4. 打分，入池

按 `topic.json` 的每一项打分（看每项的 guide，「有人搜」对照 audience.md，不凭感觉），然后：

```bash
xhs pool add --title "候选题" --insight "洞察句" --source "出处" \
  --category "voice.md 里的选题类型" --scores "有用=3,新=2,有人搜=1,话题性=1,可信=2,门槛低=1"
```

工具会校验每项的范围、算总分、判断过没过线。新东西的窗口短，默认 14 天过期；常青题可以 `--expires 60`。

## 5. 交付 3 个候选

从池子里挑过线的，最多 3 个：

```
候选 1  P7  （10/12）推荐
  洞察句：  ……
  能拿走的： 读者看完能直接用的那样东西
  类型：    voice.md 里的哪一类
  打分：    有用 3 / 新 2 / 有人搜 2 / 话题性 1 / 可信 2 / 门槛低 0
  同题现状： 小红书搜「……」前 20 条里……
  建议句式： #1 直接抄 或 #10 为什么（看 swipe.md 里本领域哪个有效）
  本篇在测： 这篇验证什么（有在跑的实验就写实验编号）
```

推荐一个，说为什么。用户点头后 `xhs pool use P7`，交给 `xhs-note`。

## 节奏和特殊规则

`voice.md` 里有「某类话题有进展那天写两篇」这类规则，照做，两篇各自过三问和打分，不互相凑数。`playbook.md` 里有关于选题的规则（比如「X 类题收藏率稳定高」），优先按它挑。

## 底线

- 没有新的、有意思的东西，就直说今天没有好题，给一个候选也行，不凑三个。
- 不搬运：同一个点别人已经讲清楚了，你的洞察句必须是别人没说的那一半。
- 打分照实打。为了过线把「有人搜」从 1 改成 2，复盘时骗的是自己。
