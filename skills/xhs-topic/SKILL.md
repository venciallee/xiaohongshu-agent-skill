# xhs-topic

选题是这个 pack 里最贵的一步：选错了，后面封面、标题、卡片做得再好也救不回来。

## 开工前

读 `$XHS_HOME/voice.md`：写给谁、方向、不写什么。voice.md 里有自己的打分表或选题规则，就以它为准，下面是默认值。再读 `$XHS_HOME/log.jsonl`（`xhs log list -n 20`），最近两周写过的题不重复，最近 5 篇用过 3 次的句式这次换掉。

## 1. 去哪找（只读）

- **X**：本人浏览器里的 For You 和 List。只挑「怎么用」的东西：工程师晒的配置、提示词、工作流、踩坑。
- **官方**：各家 changelog、帮助中心更新、best practices 文档、工程博客。新功能上线一周内是「怎么用」搜索量最大、同题笔记最少的窗口。
- **论文和技术博客**：讲清一个机制，落到一个读者能做的动作上。
- **小红书搜索**：搜索框联想词就是小白在搜什么。顺手看同题笔记现在有多少、写成什么样。

新闻、事故、融资、榜单只记下来当钩子，不当主体。

**只读不改。** 在 X 和小红书上不点赞、不转发、不关注、不评论、不发帖。用本人已经登录的浏览器，本人在场，像人一样慢慢看；不写爬虫，不用第三方抓取服务。

## 2. 只从三类里选

| 类 | 是什么 | 例子的形状 |
| --- | --- | --- |
| A 新东西怎么用 | 7 天内上线、读者马上能用 | 「X 新出的 Y，小白这样用」 |
| B 一线做法 | 工程师分享的、官方最佳实践里的具体做法 | 「做 X 的工程师自己这么用」 |
| C agent 经验 | 小白不知道的「为什么」，落到一个具体做法 | 「为什么它总说测过了」 |

纯提示词技巧、工具榜单、「AI 会不会取代程序员」不选。

## 3. 每个候选先写洞察句，过三问

洞察句是一句**原文没说、但你看完原文能说出来**的话。三问，过不了直接丢：

1. **原文里搜不到。** 原文一字一句写着的，那是摘要，不是洞察。
2. **删掉这句，整篇就成了原文翻译。** 删了没影响，说明它不是骨架。
3. **有人会反驳。** 没人会反驳的话，也没人会停下来看。

## 4. 打分，≥7 才进候选

| 项 | 分 | 怎么判 |
| --- | --- | --- |
| 能照做 | 0-3 | 读者看完 10 分钟内能做出来 = 3；要装环境 = 1；只能「了解一下」= 0 |
| 新 | 0-2 | 7 天内 = 2；一个月内 = 1 |
| 有人搜 | 0-2 | 小红书搜索联想里有 = 2；工具名有人搜但这个用法没人搜 = 1 |
| 本账号来讲可信 | 0-2 | 有原文 / 代码可引 = 2；只有二手转述 = 0 |
| 小白能上手 | 0-1 | 不需要会写代码 = 1 |

## 5. 交付 3 个候选

```
候选 1  （9 分）推荐
  洞察句：  它说「改好了」，意思是「我改完了」，不是「我验证过了」
  能复制的： 一段写进 CLAUDE.md 的「完成定义」
  类：      C agent 经验
  分：      能照做 3 / 新 1 / 有人搜 2 / 可信 2 / 小白 1
  小红书同题：搜「Claude Code 测试」前 20 条里没有讲「完成定义」的，多是安装教程
  建议句式： #1 直接抄 或 #10 为什么
  本篇在测： 「能直接抄的配置」类选题的收藏率

候选 2 ……
候选 3 ……
```

推荐一个，说为什么。本人点头后交给 `xhs-note`。

## 有两篇的日子

voice.md 里有「某类话题有进展那天写两篇」这类规则（比如 RSI 有新进展：一篇写它，一篇写科技新闻 / 技术博客 / 最佳实践），照做，两篇各自过三问和打分，不互相凑数。

## 底线

- 没有新的、有意思的东西，就说今天没有好题，给一个候选也行，不凑三个。
- 不搬运：同一个点别人已经讲清楚了，你的洞察句必须是别人没说的那一半。
