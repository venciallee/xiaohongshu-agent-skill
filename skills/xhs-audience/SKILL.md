# xhs-audience

选题里最常见的错误，是写自己觉得重要的东西，而不是读者在找的东西。这个 skill 把「读者在找什么」从感觉变成一份带出处的文件。

## 读 / 写

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | `voice.md` | 写给谁、领域（决定搜什么种子词、看哪些账号） |
| 读 | `sources.md` 的「读者在哪说话」 | 去哪看读者的原话 |
| 读 | `swipe.md`（有的话） | 对标账号，评论区从这里找 |
| 写 | `audience.md` | 模板在 `xhs defaults --dump` 导出的 audience.md |

## 什么时候跑

- 账号刚开始，还没有 audience.md。
- 每月一次（`xhs status` 会在 30 天没更新时提醒）。
- **连续几次复盘没起色**（`xhs status` 给出 deep_diagnosis）：这时先重做它，再谈别的。很多「内容不行」其实是「题没人要」。

## 1. 收原话（只读）

用用户已经登录的浏览器、用户在场，或者用户截图 / 粘贴。不写爬虫，不用第三方数据服务。

- **搜索框联想词**：拿 voice.md 里的领域词当种子，在小红书搜索框里打出来，记下联想列表和搜索结果页的相关搜索。每个种子词记原词，不改写。
- **评论区**：对标账号（swipe.md 里倍数最高的那几篇）和自己笔记下的评论，复制成一个文本文件，一行一条。
- **私信和群里的问题**：用户自己收到的，脱敏后贴进来。
- **创作中心的粉丝画像**：用户截图给你。

## 2. 跑一遍词频

```bash
xhs words comments.txt suggestions.txt --top 40
```

它列出原话里反复出现的 2-6 字词组、英文词，以及所有问句。频次是原话里的出现次数，不是搜索量；样本是谁的评论区，结论就只代表谁的读者。

## 3. 写 audience.md

按模板六节写，**每一行都有出处和日期**：

1. **他们是谁**：只写有证据的（粉丝画像、评论里自述的身份）。
2. **他们在搜什么**：种子词 → 联想词，原样。
3. **他们在问什么**：`xhs words` 挑出来的问句，按主题归类，标次数。
4. **他们卡在哪**：从问题里归纳的痛点，每条落到一个可以写的题。
5. **他们的词 vs 我们的词**：读者说「怎么装」，你习惯说「部署」。标题和开头用读者那一列。
6. **他们不感兴趣的**：数据或评论显示没人要的方向，附证据。

## 4. 交付

```
读者分析  ·  2026-11-26  ·  样本：312 条评论、14 个种子词、5 个对标账号

最大的发现
  1. 「……怎么装」类问题占问句的 38%（41/108）。现在的选题里几乎没有安装 / 上手类。
  2. 读者说「……」，我们的标题一直写「……」。搜索框里只有前者。
  3. ……

建议
  - 选题类型加一类：……
  - 标题词表：用「……」替换「……」
  - 这一类先停：……（证据：……）

已写入 audience.md。下次选题「有人搜」一项按它打。
```

结论只说样本撑得住的。300 条评论能说「这个账号的读者常问 X」，30 条不能，直说。

## 底线

- 只读，只看公开内容和用户自己的数据；私信内容脱敏，不记任何人的联系方式。
- 不编读者画像。没有证据的「他们大概是 25-30 岁的女性」不写。
