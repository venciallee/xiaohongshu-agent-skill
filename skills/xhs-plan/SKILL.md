# xhs-plan

别的 skill 执行，这个决定执行什么。每周同一天跑一次。

## 读 / 写

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | `voice.md` | 选题类型、节奏、特殊规则 |
| 读 | `playbook.md` | 验证过的规则，**优先于这里的任何默认** |
| 读 | `review.md` / `xhs review` | 最近的复盘结论 |
| 读 | `xhs exp list` | 在跑的实验还差几篇、需要哪类笔记 |
| 读 | `swipe.md` | 本领域哪些句式有效 |
| 读 | `xhs pool list` | 池子里现成的候选 |
| 读 | `xhs log list -n 14` | 最近两周发过什么，题和句式都不重复 |
| 读 | `xhs goal` | 离目标多远，节奏要不要调 |
| 写 | `plan.md` | 这周的计划 |

## 每一篇都是一次实验

每个槽位写清楚「本篇在测什么」，**一篇只测一个变量**：换句式就别同时换封面风格，换选题类型就别同时换卡片数。有在跑的实验，优先把它缺的篇数排进去，并标明实验组（`--exp E2`）还是对照组。

## 类型配比

按 voice.md 的选题类型排。没有证据之前平均分；复盘和 playbook 说某类更好，就把份额让给它。同一类型不连着排两天。voice.md 没写类型的，先问用户补上：没有类型，复盘就分不清「题不行」还是「包装不行」。

## 发布时间说清楚

**时间远没有封面和标题重要。** 小红书会持续推一篇数据好的笔记好几天，数据差的发在黄金时间也没用。用户还没把封面标题做稳就在研究几点发，是在抛光错的地方，直说。时间按读者的作息定。

```
      本篇在测：……

……
周日  —（复盘：本周 5 篇的 48 小时数据）

```

写到 `$XHS_HOME/plan.md`。这里只是计划：不排定时发布，不碰任何平台后台，每一篇由用户自己发。
