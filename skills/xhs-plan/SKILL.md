# xhs-plan

控制台。别的 skill 执行，这个决定执行什么。每周同一天跑一次。

## 输入

依次读，后面的覆盖前面的默认：

1. `$XHS_HOME/voice.md`：写给谁、方向、发布节奏（比如每天一篇、早上 9 点收稿）、特殊规则（比如某类话题有进展那天写两篇）。
2. `$XHS_HOME/review.md`：最近的复盘结论。**它比这个文件里的任何建议都优先。**
3. `$XHS_HOME/swipe.md`：同领域哪些句式起作用。
4. `xhs log list -n 14`：最近两周发过什么，题和句式都不重复。

都没有，就问本人四件事并记下来：读者是谁；想被记住的 3-4 个方向；这周遇到了什么（新工具、踩的坑、看到的好做法，这是选题的来源）；节奏。

## 每一篇都是一次实验

每个槽位写清楚「本篇在测什么」，**一篇只测一个变量**：换句式就别同时换封面风格，换选题类型就别同时换卡片数。不然复盘时说不清是哪个起了作用。

## 类型配比（技术科普号的默认）

| 类型 | 每周 | 做什么 |
| --- | --- | --- |
| 新东西怎么用 | 2-3 | 7 天内上线的功能，读者马上能做 |
| 一线做法 | 1-2 | 官方最佳实践 / 工程师分享里的一个具体做法 |
| agent 经验 / 为什么 | 1 | 小白不知道的原因，落到一个做法 |
| 一张图讲清 | 1 | 一个概念，一张能讲清楚的图 |
| 评论区来的 | 按需 | `xhs-reply` 标出来的、很多人问的问题 |

同一类型不连着排两天。复盘证据说某类不行，就把它的份额让给证据说行的那类。

## 发布时间说清楚

**时间远没有封面和标题重要。** 小红书会持续推一篇数据好的笔记好几天，数据差的发在黄金时间也没用。本人还没把封面标题做稳就在研究几点发，是在抛光错的地方，直说。

时间按读者的作息定，不按本人的。

## 输出

```
11 月 30 日 - 12 月 6 日

周一  新东西怎么用   #2 新东西怎么用   X 新出的 Y：小白怎么用
      本篇在测：新功能上线 3 天内发，曝光是否明显高于中位数
周二  一线做法       #13 一线做法      做 X 的工程师自己的 CLAUDE.md 怎么写
      本篇在测：「一线做法」类的收藏率 vs 「怎么用」类
周三  为什么         #10 为什么        为什么 AI 总说测过了
      本篇在测：问句标题的点击率
周四  ……
周五  评论区来的     #14 痛点提问      （来自 11-26 那篇评论区，34 赞的问题）
周六  一张图讲清     #9 一张图         一张图看懂 MCP
周日  —（复盘 11-26 到 12-01 的 5 篇）

规则：RSI 有进展的那天加一篇（voice.md）

说「写周一」我就开始。
```

写到 `$XHS_HOME/plan.md`，别的 skill 会读。这里只是计划：不排定时发布，不碰任何平台后台，每一篇由本人自己发。
