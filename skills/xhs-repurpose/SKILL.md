# xhs-repurpose

一份好的长内容里通常有三到五篇小红书。多数人只拿出一篇，剩下的扔了。

## 读 / 写

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | 长内容全文 | 文章、论文、转写稿、笔记 |
| 读 | `voice.md`、`playbook.md` | 写给谁、验证过的规则 |
| 写 | `xhs pool add` | 能成篇但今天不写的候选 |

## 输入

全文：文章、论文、转写稿、文档、用户自己的笔记。给的是链接就用会话里能用的抓取 / 转写工具；拿不到就请用户贴。**先读完全文再动手。**

外文源先翻译理解，但小红书上写的是讲解，不是译文。这里只取能写成笔记的东西。

## 拆，不要摘要

摘要不是笔记，没人要看摘要。逐段找能独立成篇的东西：

| 找什么 | 是什么 |
| --- | --- |
| **做法** | 读者能照做的一个动作、一份清单、一段可以照抄的东西 |
| **机制** | 「它其实是这样工作的」 |
| **踩坑** | 原文承认的失败、限制、反例 |
| **数字** | 每一个数字，连同它的口径 |
| **反常识** | 和读者直觉相反的结论 |
| **原话** | 一句已经能直接引用的话 |

先列清单，带数量，再写任何东西。少于三条，说明这份内容薄，硬拆出来的也会薄，直说。

能成篇但今天不写的，`xhs pool add` 入池，带上出处。

## 每条过洞察三问

拆出来的每一条，写一句洞察句，过 `xhs-topic` 的三问：原文里搜不到、删了它就成翻译、有人会反驳。过不了的条目，留作别的笔记里的一张卡，不单独成篇。

## 每篇完全独立

读者没看过原文，也永远不会去看。每篇都要自己站得住：不写「上一篇说过」「原文提到」当开头。出处放置顶评论。

同一份源拆出来的几篇，句式要错开（`titles.json` 里选不同的），否则一周五篇一个腔调，像内容农场，平台也把「套模板批量生产同质化内容」列为 AI 低质。

## 排一周

最反常识的那条放第一篇；踩坑放中间；机制放最后，给看过前几篇、想知道原理的人。

## 输出

```
来源：「某篇长文」（约 6000 字）

找到  做法 4 / 机制 3 / 踩坑 2 / 数字 5 / 反常识 1 / 原话 3

可以成篇（4）
  周二  #5 反常识     ……？其实反了        洞察：……
  周三  #1 直接抄     这份……直接抄        洞察：……
  周五  #4 别再这样用  别再……了            洞察：……
  周日  #9 一张图讲清  一张图看懂……        洞察：……

只能当卡片的（3）
  ……

说「写周二」我就开始。
```

然后一次写一篇，每篇都走 `xhs-note` 完整流程。不要一口气交四篇成稿：它们会读起来一模一样，用户一篇也不会发。
