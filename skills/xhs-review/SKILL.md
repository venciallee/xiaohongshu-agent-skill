# xhs-review

一个账号唯一可信的「什么有用」来源，就是它自己的数据。所有攻略里的规则，包括这个 pack 里的，都只是先验。这个 skill 负责把数据变成下一轮的改动，并且确认改动真的有用。

## 读 / 写

| | 文件 | 命令 |
| --- | --- | --- |
| 读 | `goal.json` | 目标、记数据的时间点、复盘周期、「没起色」的定义 |
| 读写 | `log.jsonl` | `xhs log list` |
| 写 | `data.jsonl` | `xhs data add` |
| 写 | `account.jsonl` | `xhs goal log --followers N` |
| 写 | `reviews.jsonl` | `xhs review --record` |
| 读写 | `experiments.json` | `xhs exp new / show / close` |
| 写 | `playbook.md` | `xhs exp close --rule`，也可以手改 |

先跑 `xhs status`，它会告诉你现在缺哪一步。

## 1. 记数据（capture_data）

数据从创作中心「数据中心 → 笔记数据」来。用户截图给你，或者用户在场时你在他已登录的浏览器里读。**不替用户登录，不用第三方数据工具抓。**

```bash
xhs data add <id或标题> --impressions 12000 --views 1500 --avg-time 30 \
  --likes 120 --collects 340 --comments 22 --shares 40 --follows 35
xhs data add --file rows.csv          # 一次记多篇，表头中英文都认
xhs goal log --followers 668          # 顺手记一次粉丝数
```

每条快照都带「发布后第几小时」。在 `goal.json` 的 `capture_hours`（默认 48 小时和 7 天）记，复盘时才能拿同一时间点比较：拿 20 小时的笔记和 7 天的笔记比，什么都说明不了。

## 2. 复盘（review）

```bash
xhs review --record      # 读 log + data，按 compare_hours 比较，摘要写进 reviews.jsonl
xhs review notes.csv     # 或者直接读一张表
```

所有判断都和**本账号的中位数**比，不用网上「点击率低于 5% 就是差」这种绝对线。

**漏斗，从前往后找第一个掉下去的：**

```
曝光  →  观看（点击率）  →  留下（收藏率、观看时长）  →  关注（涨粉 / 观看）
分发          封面标题                内容兑现                    主页
```

| 现象（和中位数比） | 问题在哪 | 下一步 |
| --- | --- | --- |
| 曝光不到一半 | 分发。先看这篇有没有违规 / 限流提示，再看话题和搜索词 | 回看 `xhs check` 的 WARN |
| 曝光正常，点击率低 | 双列流那一秒：封面大字和标题 | 开实验换句式；`xhs-viral` 看同领域封面 |
| 点进来了，收藏率和时长都低 | 内容没兑现封面 | 下一篇第 2 张就兑现 |
| 观看高、涨粉低 | **不是这篇失败了，是主页没接住** | `xhs-profile` |
| 评论率是中位数两倍以上 | 评论区有下一篇 | `xhs-reply` |
| 同一类题换了 2 种以上句式仍低 | **选题本身**，不是包装 | `xhs-audience`，重新确认读者要不要这类题 |

`xhs review` 会按 post.json 的 `category`（选题类型）和标题句式分组，最后一行就是在帮你分这两者。

**复盘也看看同领域的人。** 挑一两篇这周同题或同句式的对标笔记，用 `xhs-viral` 的方法看：封面、第 2 张、收藏/点赞比和你的差在哪。只记差别，不抄。

## 3. 一次验证一个改动（实验）

复盘发现问题之后，不要同时改五样东西。开一个实验：

```bash
xhs exp new --hypothesis "第 2 张就给可复制内容，收藏率会高过中位数" \
  --variable "第2张卡" --change "可复制内容放第2张" --metric save_rate
```

之后实验组的笔记发布时 `xhs log add post.json --exp E1`。够篇数（默认 5 篇，`goal.json` 可改）之后：

```bash
xhs exp show E1      # 实验组 vs 没挂实验的笔记：中位数、倍数、AUC
xhs exp close E1 --result supported --decision "保留" --rule "能复制的内容放第 2 张卡"
```

`--rule` 会带着证据追加进 `playbook.md`，以后选题和写稿都必须遵守。不成立的也要 close：「试过，没用」本身就是结论，能防止下个月再试一遍。

同一个变量同时只能有一个实验；同时跑两个以上实验，变量会互相干扰，`xhs exp new` 会提醒。

## 4. 对照目标

`xhs goal` 给出：现在多少、每天涨多少、按这个速度哪天到、要按期到每天需要多少。复盘结论的最后一句必须回答「离目标近了还是远了」。

## 5. 没起色时升级（deep_diagnosis）

`goal.json` 的 `stall` 定义「没起色」：默认连续 3 次复盘，近期观看中位数、近期涨粉率、每天涨粉都没有涨过 10%。`xhs status` 发现这种情况会给出 deep_diagnosis。这时**停止逐篇小修**，换一种查法：

1. `xhs-audience`：重做读者分析。读者到底在搜什么、问什么，和我们在写的对得上吗？
2. `xhs-viral`：重跑对标。同领域里现在什么在起作用？拿你最近 10 篇和同题的高倍数笔记逐项对比：选题、封面、标题、第 2 张、篇幅、发布节奏。
3. 按漏斗定位**一个**最可能的原因。
4. 只开**一个**实验去验证它，告诉用户为什么是这个。
5. 涉及换方向、改人设、改目标的，等用户点头。

## 结论怎么写

- 10 篇以内：只说「这篇哪一段掉了」，不说「X 类选题不行」。
- 10-30 篇：写成实验（`xhs exp new`），不写成「X 有效」。
- 30 篇以上：可以下结论，附证据和 n。
- 发布时间最后才看，而且只在其他都看不出东西时看。

```
诊断
  「……」     封面 / 标题：点击率只有中位数的 35%
  「……」     主页：观看 3.4 倍，涨粉率只有一半
选题层面
  「概念」类 4 篇、换过 3 种句式，倍数中位数 0.5x → 题本身的问题
实验
  E1 第2张卡：5/5 篇，收藏率 1.57 倍，AUC 1.00 → 已结束，写进 playbook
目标
  668 / 100000，每天 +12，要按期到需要每天 +273（差 23 倍）

下一步：开 E2，验证「概念类换成怎么用类」能否把观看中位数拉到 1.5 倍以上。
```

把这段发给用户；需要用户拍板的（换方向、改人设）单独列出来等回复。
