# xhs-note

把一个选题变成一篇有人点、有人存的图文。这是整个 pack 的主流程，其余 skill 都在给它供料或者把关。

用到的工具（都在本地跑，不联网，不发布）：

```bash
xhs title titles.txt --keywords "Claude Code,CLAUDE.md"   # 标题备选打分
xhs title cover.txt --cover                               # 封面大字打分
xhs human draft.txt --report -o clean.txt                 # 去 AI 腔
xhs check post.json                                       # 发布前检查
xhs cards post.json --render                              # 出卡片图（见 xhs-cards）
```

找不到 `xhs` 命令：用 pack 里的 `bin/xhs`（第一次运行会自动编译），或者按 README 装一次。**不要因为工具跑不起来就凭感觉判断字数和风险词。**

## 开工前

1. 读 `$XHS_HOME/voice.md`（默认 `~/.xiaohongshu/voice.md`）。这是账号的声音：写给谁、什么不写、卡片什么风格。没有就先让本人填 `templates/voice.md`，或者给你三篇他自己满意的旧笔记，你从里面推出来写好。
2. 读 `$XHS_HOME/house.json` 有没有（账号规则：几张卡、几个话题、身份句是否禁止）。`xhs check` 会自动用它。
3. 有 `$XHS_HOME/swipe.md` 就读。那是 `xhs-viral` 收集的同领域证据，哪些句式在这个领域真的有用，比这里的默认值可信。
4. 选题必须带一句**洞察句**。没有就回 `xhs-topic`，别硬写。没有洞察的整理，平台上一搜一大把。

## 查证，写之前

工具能做什么、某个机制怎么运作、任何数字：先查官方文档；有开源实现的，看核心代码。查不到的不写，或者写成「通常」「一般」。简化可以，说错不行。示意性的例子在卡片 note 里标「示意」。出处写进 `sources` 和置顶评论，不上卡片。

## 小红书图文的结构

小红书的钩子不在正文第一行，在双列流里：**封面大字 + 标题**同时出现，各管一件事。

```
封面大字   ≤14 字，最好 3-8 字。给眼睛：缩略图上一眼读完。通常是洞察句的反差那半句。
标题       ≤20 字（平台上限）。给搜索：前半句放读者会搜的词（工具名 + 怎么用 / 直接抄 / 设置）。
正文第 1 句  读者正在经历的场景，带搜索词。痛点问句最好用。
正文第 2 句  直接亮洞察句，并说这篇能拿走什么。
正文主体   为什么 → 怎么做（能复制的东西全文写出来）→ 边界（什么时候不灵）。
话题       按 house.json（RSI Engineering 是 5-8 个），要含搜索词。
卡片       最多 5 张含封面。第 2 张就兑现封面的承诺；一张卡一个做法；能截图的那段放卡上。
置顶评论   来源、口径、示意说明。发布后由本人自己发、自己置顶。
```

## 流程

**1. 先写洞察句，再写别的。** 封面大字、一个标题、第 2 张卡都从它来。

**2. 封面大字写 3 条，打分。** 放进 `cover.txt` 一行一条，`xhs title cover.txt --cover`。选最高分那条，除非你能说出更好的理由。

**3. 标题写 3 个，用不同句式。** 看 `xhs data --dump` 导出的 `titles.json` 里 18 个句式（或者 swipe.md 里在你领域起作用的那几个），选三个真的适合这个选题的，各写一个。不是同一句的三种改写。然后：

```bash
xhs title titles.txt --keywords "这篇的搜索词1,搜索词2"
```

最高分低于 50，说明还没有标题，换角度重写，别在这几条上抠字。三个都交给本人选，排序和理由一起给。

**4. 写正文。** 口语、短段、一段一件事。能复制的提示词、配置、命令全文写进正文，卡片上再放一份能截图的。正文不写自我介绍、不写身份句（「我是做 xx 的」）：可信度靠洞察、原文和踩过的坑。

**5. 第一人称经历要本人点头。** 「我试过」「实测」「我们团队都这么干」这类句子，除非本人告诉过你，否则一律标出来等确认；没确认的改成机制说法。确认过的原句写进 `first_person_confirmed`。

**6. 去 AI 腔。** 正文和卡片文字各跑一遍 `xhs human --report`，自动改的看一眼，标记的套话和句式自己重写，然后 `xhs detect` 看分。两轮正常；五轮说明稿子是套模板写的，换一稿，别再磨。

**7. 写 post.json。** 字段见 `examples/sample-post/post.json`。`ai_disclosure` 设 `true`：AI 参与了写作或润色，就要在 App 里声明。

**8. 发布前检查。** `xhs check post.json`。FAIL 全部修掉；每个 WARN 当着本人的面决定改还是不改，说出理由，别悄悄放过。

**9. 出图。** 交给 `xhs-cards`。

**10. 交付。** 卡片图 + 3 个标题 + 正文 + 话题 + 置顶评论 + 下面这张回执。然后停。

```
笔记就绪
洞察句：   它说「改好了」，意思是「我改完了」，不是「我验证过了」
封面：     改好了≠测过了（73 强）
标题备选： 1. Claude Code先跑测试再交活（66 可用，搜索词在最前）
           2. CLAUDE.md加这段，改完先跑测试（63 可用）
           3. AI说改好了却没跑测试？抄这段（50 可用，#1 直接抄，信息差最强但没搜索词）
正文：     505 / 1000 字，话题 6 个
卡片：     5 张，无溢出
AI 腔：    自检 81 PASS
检查：     READY（等本人确认 0 句）
本篇在测： 「能直接抄的一段配置」类选题的收藏率能不能高过中位数

选一个标题，或者告诉我改哪里。发布由你在 App 里手动完成：
上传卡片（按 01、02… 顺序）→ 填标题和正文 → 用 # 从联想里选话题 → 勾选 AI 声明 → 发布 → 自己发置顶评论。
发完回一句「发了」。
```

**11. 本人说「发了」。** 跑 `xhs log add post.json --published "发布时间"`，记下句式和「本篇在测什么」，然后提醒 72 小时后做 `xhs-review`（这个会话支持定时任务就设一个）。

## 底线

- **不发布。** 不打开创作后台点发布，不设定时发布，不写脚本自动发。平台 2026-03-10 起打击 AI 托管账号：偶发代发会被警告、限流，全流程托管直接封号。这个 pack 里 AI 是笔，不是人。
- **不编造。** 不编数字、不编经历、不编出处。缺一个数字就留 `{{你的数字}}` 并标出来。
- **不评价具体产品好坏。** 讲适合什么场景，不下优劣结论。
- **一篇只讲一件事。** 写着写着出现第二个做法，那是下一篇。说出来。
