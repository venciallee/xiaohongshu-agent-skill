# xhs-note

把一个选题变成一篇有人点、有人存的图文。这是整个 pack 的主流程，其余 skill 都在给它供料或者把关。

## 读 / 写

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | `voice.md` | 写给谁、语气、开头怎么写、什么不写 |
| 读 | `house.json` | 卡片数、话题数、身份句、卡片风格（`xhs check` / `xhs cards` 自动用） |
| 读 | `playbook.md` | 验证过的规则，**必须遵守**，和下面的默认冲突时听它的 |
| 读 | `audience.md` | 读者的词：标题和第一句用读者那一列 |
| 读 | `swipe.md` | 本领域哪些标题句式真的有效 |
| 读 | `xhs exp list` | 有在跑的实验，这篇要不要挂上、要不要按实验组的做法写 |
| 写 | `$XHS_HOME/posts/<日期>-<slug>/post.json` | 笔记本体，字段见 `examples/sample-post/post.json` 和 docs/contract.md |
| 写 | 同目录 `cards/` | 卡片 PNG（`xhs-cards`） |

用到的工具（都在本地跑，不联网，不发布）：

```bash
xhs title titles.txt --keywords "搜索词1,搜索词2"   # 标题备选打分
xhs title cover.txt --cover                         # 封面大字打分
xhs human draft.txt --report -o clean.txt           # 去 AI 腔
xhs check post.json                                 # 发布前检查
xhs cards post.json --render                        # 出卡片图（见 xhs-cards）
```

找不到 `xhs` 命令：用 pack 里的 `bin/xhs`（第一次运行会自动编译），或者按 README 装一次。**不要因为工具跑不起来就凭感觉判断字数和风险词。**

## 开工前

1. 选题必须带一句**洞察句**。没有就回 `xhs-topic`，别硬写。
2. 读 playbook.md。里面每条规则都有实验证据，比任何写作建议都可信。
3. 看 `xhs exp list`：有在跑的实验，问自己这篇是实验组还是对照组，写进 post.json 的 `exp`（对照组留空）。**一篇只挂一个实验。**

## 查证，写之前

任何事实、数字、做法：先查一手出处（官方文档、说明书、论文、原始数据；有开源实现的看代码）。查不到的不写，或者写成「通常」「一般」。简化可以，说错不行。示意性的例子在卡片 note 里标「示意」。出处写进 `sources` 和置顶评论，不上卡片。

## 小红书图文的结构

钩子不在正文第一行，在双列流里：**封面大字 + 标题**同时出现，各管一件事。

```
封面大字    ≤14 字，最好 3-8 字。给眼睛：缩略图上一眼读完。通常是洞察句里反差的那半句。
标题        ≤20 字（平台上限）。给搜索：前半句放读者会搜的词（audience.md）。
正文第 1 句  读者正在经历的场景，带搜索词。
正文第 2 句  直接亮洞察句，说这篇能拿走什么。
正文主体    为什么 → 怎么做（能复制的东西全文写出来）→ 边界（什么时候不灵）。
话题        数量按 house.json，要含搜索词。
卡片        数量按 house.json。第 2 张就兑现封面的承诺；一张卡一个做法。
置顶评论    出处、口径、示意说明。发布后由用户自己发、自己置顶。
```

voice.md 对开头、结构有自己的规定，听 voice.md 的。

## 流程

**1. 先写洞察句，再写别的。** 封面大字、一个标题、第 2 张卡都从它来。

**2. 封面大字写 3 条，打分。** 一行一条放进 `cover.txt`，`xhs title cover.txt --cover`。

**3. 标题写 3 个，用不同句式。** 句式库在 `titles.json`（`xhs defaults --dump` 导出看；有领域包就用领域包）。优先用 swipe.md 里本领域有效的句式。三个是三种句式，不是同一句的三种改写。

```bash
xhs title titles.txt --keywords "这篇的搜索词"
```

最高分低于 50，说明还没有标题，换角度重写。三个都交给用户选，附排序和理由。

**4. 写正文。** 按 voice.md 的语气；短段、一段一件事；能复制的东西全文写进正文。

**5. 第一人称经历要用户点头。** 「我试过」「实测」「我们都这么干」这类句子，除非用户告诉过你，否则一律标出来等确认；没确认的改成机制说法。确认过的原句写进 `first_person_confirmed`。

**6. 去 AI 腔。** 正文和卡片文字各跑 `xhs human --report`，标记的套话和句式自己重写，`xhs detect` 看分。两轮正常；五轮说明稿子是套模板写的，换一稿。

**7. 写 post.json。** 放在 `$XHS_HOME/posts/<日期>-<slug>/post.json`（`xhs status` 靠这个目录找草稿）。`category` 填 voice.md 里的选题类型；`testing` 写本篇在测什么；`ai_disclosure` 设 `true`（AI 参与了写作或润色就要在 App 里声明）。

**8. 发布前检查。** `xhs check post.json`。FAIL 全部修掉；每个 WARN 当着用户的面决定改还是不改。

**9. 出图。** 交给 `xhs-cards`。

**10. 交付，然后停。**

```
笔记就绪  ·  posts/2026-11-26-xxx/
洞察句：   ……
封面：     ……（73 强）
标题备选： 1. ……（66 可用，搜索词在最前）
           2. ……（63 可用）
           3. ……（50 可用，信息差最强但没搜索词）
正文：     505 / 1000 字，话题 6 个
卡片：     5 张，无溢出
AI 腔：    自检 81 PASS
检查：     READY（等确认的第一人称句 0 句）
类型 / 实验：一线做法 / E2 实验组
本篇在测： ……

选一个标题，或者告诉我改哪里。发布由你在 App 里手动完成：
上传卡片（按 01、02… 顺序）→ 填标题和正文 → 用 # 从联想里选话题 → 打开 AI 声明 → 发布 → 自己发置顶评论。
发完回一句「发了」。
```

**11. 用户说「发了」。** `xhs log add post.json --published "发布时间"`（挂实验就加 `--exp E2`）。它会打印哪几个时间点该记数据。

## 底线

- **不发布。** 不打开创作后台点发布，不设定时发布，不写脚本自动发。平台 2026-03-10 起打击 AI 托管账号：偶发代发会被警告、限流，全流程托管直接封号。这个 pack 里 AI 是笔，不是人。
- **不编造。** 不编数字、不编经历、不编出处。缺一个数字就留 `{{你的数字}}` 并标出来。
- **不评价具体产品好坏**（除非 voice.md 明确说这个号做测评）。讲适合什么场景。
- **一篇只讲一件事。** 写着写着出现第二个做法，那是下一篇，入池（`xhs pool add`）。
