# xhs-viral

研究用的 skill。别的 skill 都在写，这个去看。

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | `voice.md` | 领域、读者，决定看哪些账号 |
| 写 | `swipe.md` | 排序结果，`xhs-note` / `xhs-plan` / `xhs-audience` 都读 |
| 写 | `$XHS_HOME/data/titles.json`（可选） | 发现了句式库里没有的新句式，加进去 |
每月跑一次，或者复盘发现方向不对的时候跑；句式能管一个季度，不用天天跑。

```bash
xhs swipe captured.tsv --out ~/.xiaohongshu/swipe.md
xhs eval captured.tsv --keywords "搜索词1,搜索词2"   # 顺便检验标题打分在你的领域准不准
```

## 唯一重要的一个想法

**赞藏总数不是证据。** 小红书公开看得到的只有点赞、收藏、评论，看不到浏览量。一个 10 万粉账号的 2000 赞藏是平常日子；一个 2000 粉账号的 2000 赞藏是找到了东西，那个东西能学。

所以排序看**倍数**：这篇的赞藏 ÷ 这个账号最近 12 篇赞藏的中位数。3 倍以上是信号；1.5 倍以下是这个账号的正常水平，数字再大也学不到什么。

再看一个**收藏 / 点赞**：干货、教程、清单类笔记里，收藏明显多于点赞，说明读者是存起来要用的。这个比值高的句式，比赞藏总量高的句式更值得学。

## 1. 选账号

6-12 个，用户给或者你提议、用户点头：

- **4 个直接对标**：同领域、同读者，比本账号大一点（10 倍以内）。
- **4 个相邻**：不同领域、同一批读者。格式往往先在这里出现。
- **2-4 个大号**：只学格式，不学频率和语气。

再请用户打开自己的**收藏夹**：那是已经按他的品味筛过的语料，最快也最相关。

## 2. 去看

用这个会话里有的浏览方式：用户自己的 Chrome（已登录）、内置浏览器，或者用户截图 / 粘贴给你。

**这几条没有商量余地：**

- **不替用户登录，不要密码。** 需要登录的页面，用用户已经登录的浏览器，用户在场。
- **是阅读，不是抓取。** 十来个账号、每个十几篇，人的速度。不写爬虫，不用第三方抓取 / 数据服务，不放后台循环。平台对自动化很敏感，用户的账号就是代价。
- **只读。** 不点赞、不收藏、不关注、不评论。
- **学句式和结构，不抄标题和内容。** swipe file 里每一行都写明来源账号。

**每篇记什么：**

| 列 | 说明 |
| --- | --- |
| account | 账号名 |
| followers | 粉丝数（主页上） |
| median | 这个账号最近 12 篇赞藏的中位数，扫一眼取中间那个 |
| likes / collects / comments | 这篇的点赞、收藏、评论 |
| title | 标题原文，错字也照抄 |
| cover | 封面大字（可选） |

median 是最重要的一列。没有它就退回到按粉丝数比（赞粉比），两种倍数不能放一起比，工具会提示。

格式（TSV，表头中英文都认）：

```
account	followers	median	likes	collects	comments	title
@某账号	3200	180	820	1900	64	Claude Code总说改好了？这段直接抄
```

## 3. 排序

```bash
xhs swipe captured.tsv --out ~/.xiaohongshu/swipe.md
```

它算倍数和收藏/点赞，用 `titles.json` 的 18 个句式给每个标题归类，打标题分，然后对比上 1/3 和下 1/3。

## 4. 只说三件事，说得小心

1. **哪些句式在上 1/3 更多**，带次数。两个句式在 6 个账号里各出现 4 次是发现；一个出现 2 次不是。
2. **上 1/3 结构上有什么共同点**是下 1/3 没有的：标题长度、带不带数字、收藏/点赞高不高、封面是反差句还是清单。
3. **未归类的那几行**：要么是噪音，要么是 `titles.json` 里还没有的句式。手读。这是最值钱的一栏；发现新句式，加进 `$XHS_HOME/data/titles.json`。

然后用大白话说样本量和可信度。40 篇、6 个账号能支撑一个说法；12 篇不能，说出来，这就是研究和算命的区别。

## 5. 顺手检验一下标题打分

```bash
xhs eval captured.tsv --keywords "本账号的搜索词"
```

它告诉你 `xhs title` 的打分在你的领域能不能分开上 1/3 和下 1/3（AUC，0.5 等于抛硬币）。这套打分还没在真实小红书数据上验证过，这一步就是验证。结果差，就照实告诉用户：打分只能挡烂标题，挑标题靠他自己的判断和复盘数据。

## 6. 变成能写的东西

前三个句式，各写一个**本账号自己的版本**：他的选题、他的洞察、他能拿出来的原文，套在这个结构里，交给 `xhs-note`，句式编号写上。

永远不要交回去一句「照着这篇写一篇」。交回去一个他明天就能用的标题。

```

倍数 3 倍以上
  23.3x  藏/赞 2.33  #9  一张图讲清   @某账号D   一张图看懂MCP到底是什么
  15.1x  藏/赞 2.32  #1  直接抄       @某账号A   Claude Code总说改好了？这段直接抄
  ...

上 1/3 更多的句式
  #1 直接抄   上 5 / 下 0
  #9 一张图   上 4 / 下 1
  收藏/点赞中位数：上 1/3 2.16，下 1/3 0.82

未归类（6）
  其中两条是同一个形状、titles.json 里没有：「X 的 N 个隐藏用法」。值得加。

```

写到 `$XHS_HOME/swipe.md`。`xhs-note` 和 `xhs-plan` 都会读它：跑过一次之后，整个 pack 用的就是本账号领域里的证据，而不是默认值。
