# xhs-reply

评论区是下一篇选题最便宜的来源，也是一个号「有没有活人」最直接的证据。

## 先说边界

平台 2026-03-10 的 AI 托管治理公告点名了「在评论、私信、群聊中模拟真人互动」。所以这个 skill：

- **只写草稿，本人改过、本人亲手一条条发。** 不批量，不自动，不用任何工具代发。
- **只处理自己笔记下的评论。** 不给别人的笔记写评论去「互动引流」。Instagram 那套「每天去 10 个账号下评论」的打法，搬到小红书上用 AI 批量写，正是平台在打的东西，所以这个 pack 里没有它。
- 草稿要短，像本人会说的话。本人改成自己的话再发，比照抄好。

## 输入

本人粘贴或截图评论，带昵称更好。不用浏览器去抓评论区。

## 先分类，说出每类多少条

| 类 | 是什么 | 怎么办 |
| --- | --- | --- |
| **问题** | 一个很多人都会问的问题 | 在评论里直接答完。点赞多的，标成下一篇选题交给 `xhs-topic` |
| **纠错** | 说你哪里写错了 | 先查证。对方对，就认、谢、改，发一条更正评论并置顶。不删原评论 |
| **补充** | 加了信息或自己的经验 | 最认真的回复给它 |
| **反对** | 不同意你的观点 | 先承认对方说对的部分，用他的话；再说你的依据。只回一次 |
| **求资源** | 「求链接」「怎么领」「发我一份」 | 在评论里直接说名称和怎么搜到。**绝不写「私信领取」「已私」**：那是导流 |
| **支持** | 「有用」「收藏了」 | 点个赞，或者几个字 |
| **噪音** | 广告、引战、阴阳怪气 | 不回。回复就是给它曝光。违规的举报 |

按这个顺序写，写到不值得写为止。

## 回复怎么写

- **在评论里把问题答完。** 别让人去私信才能拿到一个本可以公开说的答案。
- **长度跟着对方。** 四个字的评论不配四行的回复。
- **认错要快。** 技术科普号被指出错误，公开认、改、置顶更正，比辩解涨的信任多。
- 不写「谢谢宝子」「亲亲」这类客服腔。跑一遍 `xhs human`。

## 置顶评论

每篇发完由本人自己发一条并置顶：出处（文档名 / 文章标题，网址可能被判导流，写名称就够）、示意说明、口径。`xhs-note` 已经在 post.json 的 `pinned_comment` 写好了草稿。

## 输出

```
评论  ·  42 条  ·  问题 4 / 纠错 1 / 补充 3 / 反对 1 / 求资源 6 / 支持 25 / 噪音 2

纠错（先处理）
  @某某 —「CLAUDE.md 不是每次都会读吧？子目录里的呢」
  查证：对方说得对一半。根目录的会自动加载；子目录的按文档说明在用到时加载。
  草稿 > 对，我写简单了。根目录的会自动读，子目录的是用到那个目录时才读。正文已改，谢谢指出。
  → 改正文，置顶这条

问题 → 下一篇
  @某某 —「没有测试的项目怎么写？」  31 赞
  这是一篇，不只是一条回复。交给 xhs-topic：#14 痛点提问。
  草稿 > 写你平时手动检查的那一步，比如「npm run build 没报错再说完成」。下一篇专门讲。

求资源（6）
  草稿 > 文件名就叫 CLAUDE.md，放项目根目录，内容就是第 3 张图那段，截图就能用。

噪音（2）  不回。
```

然后停。本人改、本人发。
