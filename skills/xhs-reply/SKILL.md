# xhs-reply

评论区和私信是下一篇选题最便宜的来源，也是一个号「有没有活人」最直接的证据。

## 读 / 写

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | `voice.md` | 语气、不能碰的话题 |
| 读 | 用户贴的评论 / 私信 | 原话，最好带昵称 |
| 写 | `xhs pool add` | 很多人问的问题进选题池 |
| 写 | 原话文本（可选） | 给 `xhs-audience` 的 `xhs words` 用 |

## 先说边界

平台 2026-03-10 的 AI 托管治理公告点名了「在评论、私信、群聊等场景中模拟真人互动」。所以这个 skill：

- **只写草稿，用户改过、用户亲手一条条发。** 不批量，不自动，不用任何工具代发。
- **只处理用户自己收到的评论和私信。** 不给别人的笔记写评论去「互动引流」：用 AI 批量写这种评论，正是平台在打的东西。
- **私信不导流。** 不写「私信领取」「加我」，不在私信里留联系方式、站外账号或链接。导流规则覆盖私信和用户资料。
- 草稿要短，像用户自己会说的话。

## 输入

用户粘贴或截图评论、私信。不用浏览器去抓评论区。私信里的个人信息脱敏后再处理。

## 先分类，说出每类多少条

| 类 | 是什么 | 怎么办 |
| --- | --- | --- |
| **问题** | 很多人都会问的问题 | 在评论里直接答完。点赞多的进选题池：`xhs pool add` |
| **纠错** | 指出你写错了 | 先查证。对方对，就认、谢、改，发一条更正评论并置顶。不删原评论 |
| **补充** | 加了信息或自己的经验 | 最认真的回复给它 |
| **反对** | 不同意你的观点 | 先承认对方说对的部分，用他的话；再说你的依据。只回一次 |
| **求资源** | 「求链接」「怎么领」「发我一份」 | 在评论里直接说名称和怎么搜到。**不写「私信领取」「已私」** |
| **商务合作** | 品牌 / 机构私信谈合作 | 见下面 |
| **支持** | 「有用」「收藏了」 | 点个赞，或者几个字 |
| **噪音** | 广告、引战、阴阳怪气 | 不回，回复就是给它曝光。违规的举报 |

按这个顺序写，写到不值得写为止。

## 商务合作私信

号做起来以后会有。草稿只做三件事：

1. 礼貌确认收到，问清楚对方是谁、要什么形式、预算范围和时间。
2. 提醒用户：商业合作按平台规则走官方合作渠道并标注；不在私信里交换站外联系方式。
3. 对照 voice.md「不能碰的」和账号方向，说出这个合作和账号定位合不合。接不接由用户决定。

## 回复怎么写

- **在评论里把问题答完。** 别让人去私信才能拿到一个本可以公开说的答案。
- **长度跟着对方。** 四个字的评论不配四行的回复。
- **认错要快。** 被指出错误，公开认、改、置顶更正，比辩解涨的信任多。
- 不写「谢谢宝子」「亲亲」这类客服腔。跑一遍 `xhs human`。

## 置顶评论

每篇发完由用户自己发一条并置顶：出处（写名称和标题即可，网址可能被判导流）、示意说明、口径。`xhs-note` 已经在 post.json 的 `pinned_comment` 写好了草稿。

## 输出

```
评论 42 条 + 私信 5 条  ·  问题 4 / 纠错 1 / 补充 3 / 反对 1 / 求资源 6 / 商务 1 / 支持 29 / 噪音 2

纠错（先处理）
  @某某 —「……」
  查证：对方说得对一半。……
  草稿 > 对，我写简单了。……正文已改，谢谢指出。
  → 改正文，置顶这条

问题 → 下一篇
  @某某 —「……」  31 赞
  这是一篇，不只是一条回复。已入池 P12。
  草稿 > ……下一篇专门讲。

商务（1）
  某品牌，想做……  和账号方向：基本一致 / 不一致，因为……
  草稿 > 你好，收到。方便说下合作形式、时间和预算范围吗？我们按平台的合作流程来。

噪音（2）  不回。
```

然后停。用户改、用户发。
