# xhs-profile

主页不是让人逛的店面，是一个**决定页面**：读者从一篇笔记点进来，三秒内回答一个问题：这里还有更多这样的吗，是给我的吗。

## 读 / 写

| | 文件 | 用途 |
| --- | --- | --- |
| 读 | 用户截图 / 粘贴的主页 | 昵称、简介、头像、置顶、合集、九宫格、近 20 篇标题 |
| 读 | `voice.md`、`audience.md` | 写给谁、读者用什么词搜 |
| 读 | 同目录 `rubric.json` | 评分表 |

复盘里「观看高、涨粉低」的那种笔记，问题不在笔记，在这一页。

## 输入

请用户截图或粘贴：昵称、简介、头像、置顶了哪几篇、合集名、最近 9 篇的封面（九宫格截一张就行）、最近 20 篇的标题。

不替用户登录，不改任何资料。每个字段由用户自己去 App 里改。

## 打分

读同目录的 `rubric.json`：11 项、100 分，每项写了满分长什么样、通常怎么丢分。每项都打，给表、给总分。**打狠一点**：第一次多数主页在 30-50 分，宽松的分数没有用。

```
主页评分  41/100

  简介第一行     4/14   一排身份标签，看不出给谁看
  昵称           3/12   只有英文名，读者搜领域词搜不到
  置顶           0/12   没置顶
  领域垂直度     8/10   近 20 篇 18 篇在同一个领域
  封面一致性     9/10
  ...
```

## 按丢分多少排序重写

不要一次全改，用户得一个个去 App 里改。按丢分从多到少：

1. **简介第一行**：给谁看、看完得到什么。写 3 个版本。不写职位，不写形容词。
2. **昵称**：英文名保留，但读者会搜的中文领域词要出现在昵称或简介第一行里。给 3 个选项。改昵称有频率限制，先确认用户愿意改。
3. **置顶**：从已发笔记里挑，分工明确：收藏最高的那篇（证明有用）、最适合新读者的那篇（从哪开始）、最能代表这个号观点的那篇。数量按 App 当前允许的来。这是整页回报最高的改动，只要点几下。
4. **合集**：按读者的问题命名，「新手入门」「直接抄的清单」，不按日期。
5. **封面一致性**：如果最近 9 篇不像一个号，回 `xhs-cards` 统一 `card_style`，以后都用它。
6. 剩下的按表来。

简介里**不放联系方式、不放站外账号**：平台导流规则覆盖用户资料。

## 输出

评分表，然后按修复顺序给可以直接复制的文案，每段都过一遍 `xhs-human`。最后重新打分，**照实说差值**：改完是 72 不是 95，就说 72，并说剩下的需要什么，通常是更多同领域的笔记、一个还没写的「新读者从这里开始」那篇、和一段稳定更新。那些不是改文案能解决的。
